# Oracle ARM64 pilot troubleshooting

| Symptom | Check and safe response |
| --- | --- |
| Preflight rejects eligibility | Read current Oracle console/pricing terms, account aggregate usage and remaining quotas; fill in actual values/date. It cannot verify billing. Never set `FREE_TIER_VERIFIED=yes` merely to bypass the check. |
| A1 capacity unavailable | Retry later in the eligible home region or wait for capacity. Do not select a paid shape, create extra accounts or bypass quotas automatically. |
| Host architecture rejected | `uname -m` must be `aarch64`; the native Oracle option is not a Windows/x64 image. The explicit non-ARM preflight switch is for configuration validation only, not deployment/performance claims. |
| Docker build cannot resolve Debian/npm/browser hosts | Check DNS, outbound rules and trusted proxy policy. This workspace's container DNS failed on `deb.debian.org`. Do not disable certificate/package verification or use untrusted browser mirrors. GitHub ARM CI is a separate validation path. |
| Chromium sandbox/namespace startup fails | Inspect private container logs, kernel user-namespace availability, OCI Ubuntu security policy and the exact pinned `seccomp.json` mount. Use a supported maintained kernel/image and a narrowly reviewed namespace policy. Do not disable the Chromium sandbox, host AppArmor, seccomp or TLS. The local x64 system browser failed due to a misconfigured SUID sandbox and was recorded as a failed probe. |
| Browser launch says limit/calibration blocked | Review configured ceiling, effective limit and calibration status. The uncalibrated pilot ceiling is one, not three. Run a local probe on the actual server and review its complete report. A failed/zero/expired/nonmatching calibration is not permission to increase the limit. |
| Low-memory or low-disk alert | Check dashboard, `free -h`, `df -h`, `sudo docker stats`. Stop unnecessary profiles/workloads, free only known disposable files, inspect volume/log growth. Never delete session files, ownership locks or keys to free space casually. A memory safety stop removes desired-running intent and needs manual review. |
| CPU pressure blocks launch | Wait for startup spikes to settle, investigate heavy pages/viewer rendering and reduce active count. Do not increase quota above remaining free entitlement or remove safety limits. |
| Viewer page returns 401 | Reconnect using the management token, create a viewer session and follow its link on the same origin. Cookie expires after 15 minutes; opening a bookmark alone does not authenticate. |
| Viewer WebSocket rejects or disconnects | Use the same 127.0.0.1 hostname/port and SSH tunnel. Check Host/Origin preservation and WebSocket forwarding. HTTP tunnel uses `COOKIE_SECURE=0`; an HTTPS gateway uses 1. Do not expose 5900/6081 directly as a workaround. |
| Viewer connects but wrong browser is visible | Use that profile's **view** control to bring its page forward; all profiles share one private desktop. Check Openbox/Xvfb process health. Login status cannot be inferred reliably from the dashboard. |
| Keyboard/mouse problems | Focus the viewer canvas; check browser window placement/scaling and viewer connection state. Clipboard synchronization/file transfer are intentionally unavailable. Never install a credential capture workaround. |
| Browser/session disappeared after reboot | Check stable vault keys, same named volume/project, desired-running intent, crash budget, resource blocks and real site expiry. Health/live alone does not prove browsers restored. Restore an offline backup if state is invalid; do not reset encrypted files blindly. |
| Exit code 73 / lock held | Another service/probe owns the volume. Stop its actual owner cleanly. Never delete `worker.lock` or SingletonLocks or mount the volume on two workers. |
| Recovery exhausted | Inspect error/crash history and resource readings. Fix the cause, then explicitly stop/start/restart. Repeated resets are not a substitute for fixing a crash loop. |
| Docker is unhealthy but still running | Docker health checks report health; they do not auto-restart a hung process. Investigate and safely restart the service after considering unsaved forms. |
| Soak or comparison refuses configuration | It requires stopped, already configured `https://fixture.invalid/profile-NN` slots and test-only fixture endpoints. Use a separate disposable project/volume; never overwrite real accounts to make the test pass. |
| Report says completed but zero capacity | Probe completion means measurements ended, not a pass. Check `recommendedLimit`, successful steps, errors and architecture. Soak requires its separate `pass:true`. |
| Source research / native Oracle tests unavailable | See the dated test report. No connected Oracle instance/API permission exists here, and official Oracle hosts were proxy-blocked. Run the documented console and native-server checks; do not translate x64, emulated or ARM CI results into Ampere capacity claims. |

Use `sudo docker compose -f deployment/oracle-free/compose.yaml logs --tail=100 manager` privately. Do not paste management/vault keys, session dumps or personal-site URLs with access tokens into public issues. Browser/profile logs may contain sensitive details even though the dashboard does not display session tokens. Retain a failing fixture report with architecture, versions, safe resource metrics and exact elapsed duration when reporting a bug.
